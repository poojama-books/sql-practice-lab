# The SQL Practice Lab: Companion Files

Practice database and solutions for **The SQL Practice Lab** by Pooja M A.

The book has 205 problems built on **NovaCart**, a fictional online store:

- 150 Exercises
- 22 Analyst Challenges
- 8 Business Cases
- 10 Debug Challenges
- 15 Interview Challenges

This repository gives you the NovaCart database and every solution from the book, in three versions: **PostgreSQL**, **MySQL** and **SQL Server**.

## Pick your database

Use only the folder for the database you have installed. Each folder works on its own.

| Database   | Folder                       | Version needed       |
|------------|------------------------------|----------------------|
| PostgreSQL | [`postgresql/`](postgresql/) | PostgreSQL 10 or later |
| MySQL      | [`mysql/`](mysql/)           | MySQL 8.0 or later   |
| SQL Server | [`sqlserver/`](sqlserver/)   | SQL Server 2016 or later |

## What is in each folder

```text
postgresql/
├── README.md                  how to run the files in PostgreSQL
├── novacart_postgresql.sql    creates and loads the NovaCart tables
├── all_solutions.sql          every solution in one file
└── solutions/
    ├── ch04_retrieve_the_right_data.sql
    ├── ch05_ask_better_questions_with_where.sql
    ├── ...                    one file per chapter
    └── ch27_sql_interview_lab.sql

mysql/        same layout, written for MySQL
sqlserver/    same layout, written for SQL Server
```

Every query in a folder is written for that database and runs as-is. You never need to edit a query or uncomment another database's version.

## Quick start

1. Create an empty database called `novacart`.
2. Run the setup script from your folder, for example `postgresql/novacart_postgresql.sql`.
3. Check the row counts in the table below.
4. Open the chapter file you are working on, for example `solutions/ch10_group_the_business.sql`.

The README inside each folder has the exact commands for that database.

## How a solution looks

Each problem has the same number and title as in the book, followed by its **Check Your Result** row count:

```sql
-- ----------------------------------------------------------------------
-- Exercise 52 - Count Active Payment Methods
-- Check Your Result: 1 row
-- ----------------------------------------------------------------------
-- Solution
SELECT
    COUNT(DISTINCT payment_method) AS active_payment_methods
FROM payments
WHERE payment_status = 'Successful';
```

- If your query returns the same rows, it is correct, even if it is written differently.
- **Debug Challenges** show the broken query inside `/* */` so it does not run, followed by the correct query.
- **Exercise 76** uses today's date, so its row count depends on the day you run it.
- Try each problem yourself before opening the solution.

## About the ID columns

Every ID column is an identity column, so the database numbers new rows for you:

| Database   | ID column definition                 |
|------------|--------------------------------------|
| PostgreSQL | `GENERATED BY DEFAULT AS IDENTITY`   |
| MySQL      | `AUTO_INCREMENT`                     |
| SQL Server | `IDENTITY(1,1)`                      |

The setup scripts load each row with its own ID, so the IDs match the book (customer 101, order 304 and so on). A row you add without an ID gets the next number. The first new customer gets ID 127.
